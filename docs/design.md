# bot-console: per-repo design (v2)

**Date:** 2026-10-13. **Status:** Draft, design only.
**Cross-repo design (the source of truth for auth, permissions, and the API):** [../../docs/design-bot-agent-deploy.md](../../docs/design-bot-agent-deploy.md). This file covers only what changes inside this repo.

## Direction

bot-console stops reading Postgres directly and becomes a BFF client of bot-api-server (decision D6). It holds no database login, no OAuth client secret, and no permission logic. It may hide controls the user's role cannot use, but bot-api-server decides.

## Transition

| Step | Pages | Data source | Status |
|---|---|---|---|
| Today | Overview, per-host, Services, Processes | `cluster_metrics` on pi4 via `src/lib/server/db.ts` (read-only login) | Superseded |
| v2 step 1 | Sign-in, projects, members, hosts, join tokens (new) | bot-api-server | Done |
| v2 step 2 | Overview, per-host, Services, Processes, page by page | bot-api-server `/v1/.../metrics` and `/health`, after bot-agent data is in `deploybot.metrics` | Done 2026-10-14 (Joe: old pages deleted) |
| v2 step 3 | Remove `src/lib/server/db.ts` and the `cluster_metrics` login from `.env` | — | Done 2026-10-14 (Joe: old pages deleted) |

Steps 2 and 3 landed together. The console no longer reads Postgres. Host overview and processes are tabs on `/hosts/[id]`. Services is a tab on `/projects/[id]`. Both are fed only by bot-api-server. `BOT_API_URL` is required.

## Auth (BFF)

- New routes: `/signin` (Google only for now; GitHub later), `/auth/google/callback`, `/signout`, `/device` (the device-code approval page for MCP clients: sign in, enter the code, approve; umbrella §7), `/oauth/consent` (MCP browser consent: client name marked unverified, full redirect host, Allow or Deny), `/account/apps` (Connected apps, linked from the header account menu, with a revoke action), and `/invite/[token]` (join a project from an invite link: lookup on load, Join posts accept, then 303 to that project).
- Sign-in: a server route calls bot-api-server `GET /v1/auth/google/start`, then redirects. The callback route posts `code` and `state` to `POST /v1/auth/google/callback` and receives the session token once.
- Cookie `bot_session`: `HttpOnly`, `SameSite=Lax`, `Path=/`, `Max-Age=604800`, and `Secure` when the origin is HTTPS (the dev `:5180` is HTTP over the tailnet, so no `Secure` there).
- Public site pages `/about`, `/privacy`, `/terms` (route group `(site)`, own layout; listed in `SITE_PATHS` in `src/lib/server/session.ts`, which a test ties to the route folders): `hooks.server.ts` renders them before reading the cookie, so they never call the API, keep the shared security headers and theme marker, and drop the global `noindex` meta. The root layout renders only the page for `(site)` routes. Their components import only `$lib/site` and `$lib/legal`, so stage 2 can move them to a separate static site. The About pitch diagram is inline SVG generated by `scripts/build-pitch-diagram.mjs` from `design/pitch-diagram*.svg` (edit those, run `pnpm build:diagram`; `tests/pitch-diagram.test.ts` fails on drift): its classes map to theme tokens so it follows the theme switch, the title is the accessible name and the desc the description, and only one of the two layouts is displayed at a time. Since `docs/spec-about-page.md` (umbrella) the diagram shows only the flow; its former Security, Resilience, Visibility and Teams panels are the page's What you get cards. The deploy capture is a real dev screenshot at `static/brand/about-deploy-result.webp` (under `/brand/*`, which the deploybot.dev Caddy apex block already serves) (WebP, explicit width and height, under 200 KB, checked by `tests/about-page.test.ts`), and the two MCP captures (confirm plan, refusal) are text blocks with the exact dev output, not images. Lucide icons come from `@lucide/svelte/icons/*`, the only package import the public pages allow besides `svelte`.
- `hooks.server.ts`: read the cookie, call `GET /v1/me` (cached for each request), and put the user in `event.locals`. Unauthenticated page requests redirect to `/signin`. `/api/*` returns 401. `safeNext` allows `/invite/<token>` only when the token is 43 base64url characters, with no query or extra segment. A signed-out `/invite/` request returns that redirect itself with `Cache-Control: no-store`, `Referrer-Policy: no-referrer`, and `X-Frame-Options: DENY`. `/signin` responses send `Referrer-Policy: no-referrer` and `Cache-Control: no-store`, so `next` is not sent on to Google.
- Every server-side call to bot-api-server sends `Authorization: Bearer <cookie value>`. Each call also sets `X-Forwarded-For` to `event.getClientAddress()` when that value is an IP, and does not copy `X-Forwarded-For`, `Forwarded`, `X-Real-IP`, or other client-address headers from the caller. The browser never talks to bot-api-server.
- Mutating forms send one `idempotency_key` per click. Catalog run, stop, and restart keep the same key from the time the dialog opens until that post succeeds, and ignore a second click while it is in flight. A failed post retries with that key. After success the dialog mints a new key. Logs omit the key. SvelteKit's origin check covers CSRF for form POSTs.

## New pages

- **Projects:** list, create (the creator becomes owner), rename and delete (owner).
- **Project page loading:** each tab fetches only the lists it shows (Hosts: hosts; Services: hosts, then services; Catalog: hosts, members, catalog, and one `services?view=deploybot&limit=200` call that tells which image entries have a container on which host (an incomplete or failed answer leaves the actions enabled); Members: members, invites; Join tokens: hosts and join tokens (a failed host list is a Notice on that tab; the Add a host guide starts open only when that list loaded and is empty); Settings: env sets, registries, files), after the project itself. Calls that do not depend on each other run in parallel; only Services waits for the host list. A failed list becomes that section's message. The catalog form asks for env-set names and file names with their own actions when the dialog opens. Those names are not loaded with the catalog tab. The Image field asks for registry tags (`?/catalogImageTags`) and a picked tag's digest (`?/catalogImageDigest`) the same way, through hidden forms (`ImageLookupPost.svelte`) placed after the save form.
- **Members:** list; admins add, remove, and change viewer/admin roles; the owner transfers ownership. Admin+ creates an invite link (viewer or admin, expiry 1, 7, or 30 days, uses 1, 5, or 25). The url is shown once in that dialog and is not put in the page URL, a cookie, or a log. Closing the dialog clears it; opening the dialog again shows the empty form. A url is shown only when its origin is this console's origin and its path is `/invite/<token>`. Pending invites list role, creator, expiry, uses, and status, and revoke with an icon-only Ban action.
- **Hosts:** per project: status (online, offline, or asleep for `always_on=false`), last seen, agent version; admin+ revokes a credential.
- **Join host:** admin+ sees an Add a host guide on the Join tokens tab. Its first line says to run the commands below on the host being added (for example over `ssh -t`). The guide starts open only when the host list loaded and is empty. A failed host list is a Notice and leaves the guide closed. Creating a join token shows it **once**, with an enrol command that does not contain the token. The API install command is not shown. The server in the enrol command is taken from that API command (a loopback `ws://` server adds `--insecure-dev`), or the enrol command uses `<your server URL>` when the command is missing or rejected, or when the server value contains the token. An empty Hosts list with no host-list message links an admin to Join tokens and tells a viewer to ask a project admin. The page never shows the token again.
- **Ops (phase 2):** logs for every member, viewers included. Deploy (by container name: adopt if it exists, create otherwise) for admin+. Run, stop, and restart for admin+ on `owned` services. Results come back inline. History reads `GET /v1/projects/{id}/audit`. This replaces the spec-v1 rule that "the dashboard does not drive ops".

## Env

`BOT_API_URL` is required. There is no Postgres URL or password. No OAuth secrets (they live on bot-api-server). An unset or invalid `BOT_API_URL` makes every route except static assets return 503.

## Components

Pages render on the server. JavaScript is required for dialogs, the theme switch, and chart refresh. Search, sort, paging, tabs, and filters stay in the URL, and every write is still a SvelteKit form action. Shared pieces live in `src/lib/components/` and are built on the shadcn-svelte primitives in `src/lib/components/ui/` (generated; do not edit them). The exception is `ui/combobox`, written by hand on bits-ui `Combobox` because shadcn-svelte has no free-text combobox: `Root` (`open`, `onPick`), `Input` (bindable free-text `value`, `role="combobox"`, `aria-expanded`, `aria-controls` naming the listbox), `Content` (with an `aria-label` and an optional `footer` outside the listbox, which holds only options) and `Item`. bits-ui highlights the first option on its own; the primitive hides that highlight and its `aria-activedescendant` until the user moves with the arrow or Page keys (the first ArrowDown shows the first option, the first ArrowUp the last), and until then Enter closes the list and submits the form with the text as typed, so a typed reference is never swapped for an option. Home and End move the caret. Colours come only from the tokens in `src/app.css`. Icons are `@lucide/svelte`. `cn()` is in `src/lib/utils.ts`. Command lines, ports, pids, tokens, and enrol commands use the monospace stack. Dialogs mount only while open and use the generated portal.

Live is polling, not streaming: `src/lib/logs-poll.ts` runs one request at a time, starts the next 3 s after the previous answer, pauses while the tab is hidden, stops when the drawer closes, and turns Live off after 15 minutes or 3 failures in a row. Turning Live on and a visible tab keep that minimum gap: they fetch at once only when 3 s have passed since the last answer, otherwise after the rest of it (the first fetch on open is immediate). `src/lib/logs-load.ts` (`LogsLoader`) posts the action with injected `fetch`, `deserialize` and `goto`, keeps the view, aborts on close and drops late answers, and follows a redirect only to a same-origin path (else the generic error). Lines (spec rev 2): the drawer's Lines picker (the vendored Select) offers 200, 500 and 1000, plus 2000 for images, and resets to 200 on each open. Every Live poll replaces the view (there is no timestamp or cursor to join answers on), so Live only shows the newest N lines and the picker offers only 200 and 500 while it is on (spec option B). `src/lib/log-lines.ts` holds the choices per kind, the Live choices, the picker state (`{choice, beforeLive}`) and its Live rules: turning Live on with 1000 or 2000 switches the picker to 500 and remembers the earlier choice; turning Live off with the switch restores it and fetches it once; nothing remembered (the choice was 200 or 500, or the user picked again during Live) means no change and no fetch; Live ending by itself (15 minutes or 3 failures) keeps 500. Every fetch, including the first one and Refresh, asks for the current choice. The `catalogLogs` action sends `{host_id, lines}` when `lines` is posted and answers 400 with no API call when the value is not in the kind's set (exact decimal text); without `lines` it sends `{host_id}` and the API default (200) applies. `LOG_LINE_CAP` in `shape.ts` is 2000, so a 2000-line image answer is not cut by the console (programs stay at 1000 by the API). A `truncated` answer shows `Only the newest lines that fit in 64 KB are shown.` (the agent-protocol 64 KiB answer limit). A choice made while a fetch runs is fetched once that fetch ends; during Live that fetch counts as a Live poll. `chooseLines` and `switchLive` in `logs-load.ts` apply these rules to the loader and the poller, and the poller's `fetchSoon` queues one fetch behind a running one. Each update replaces the view; the scroll-follow rule, the status texts and the redirect check are in `src/lib/log-view.ts`. The drawer has one always-present `role="status"` region (error, Live end note, or a screen-reader-only `Loading logs…`); the Live note and update time sit in a separate line that is not announced. `src/lib/ansi.ts` removes terminal escape sequences (CSI including a cut-off one at the end, OSC ending in BEL or `ESC \`, two-byte escapes) and C1 controls from log lines before `displayText`. `displayText` in `src/lib/server/shape.ts` turns a tab into a space and every other control character into U+FFFD in every field it cleans (log lines, process names and cmdlines, deploy plans, names). ## Theme

Cookie `bot_theme` is `system` (the default), `light`, or `dark`. Any other value counts as `system` and is never written back raw. `POST /theme` is public. It sets the cookie (`HttpOnly`, `SameSite=Lax`, `Path=/`, max-age one year, `Secure` only when the request is https) and redirects to a safe `next`, or to `/` when `next` is unsafe. The server writes `class="dark"` for dark, nothing for light, and `data-theme="system"` for system. An inline script in `src/app.html` (`nonce="%sveltekit.nonce%"`) adds `.dark` before paint when the choice is system and the OS prefers dark, and it follows later OS changes only while that attribute is still `system`. `ThemeSwitch` sets the class immediately, then posts `/theme` (`name="theme"`, hidden `next`) with `use:enhance` and does not reload the page. At 640 px and below the three choices are icons only, and the switch sits on the next header line. The signed-in row wraps, and a long account name truncates.

## Times

Absolute timestamps, including Last seen and chart axis labels, render in the viewer's time zone. `LocalTime` is the shared piece. The layout load reads cookie `bot_tz` (an IANA name; anything else is ignored) and otherwise uses the server's zone, so the server HTML and the first client render match. After mount, a browser whose zone differs switches the visible times and stores `bot_tz` (`SameSite=Lax`, `Path=/`, max-age one year, `Secure` only on https, not `HttpOnly`). The date shape stays day-month-year with a 24-hour clock. The zone abbreviation on a full timestamp is the viewer's.
